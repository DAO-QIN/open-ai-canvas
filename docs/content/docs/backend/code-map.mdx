# 代码功能地图

## 可灵全能视频协议

- `backend/internal/app/channel_models_test_call.go`、`web/src/pages/admin/components/channel-model-editor.tsx`：管理端可填写测试内容，视频使用默认参数生成并保存为当前账号的资源，支持预览下载；不创建模型价格、用户任务或站内计费订单。

- `plugin-packages/kling-video-omni/`：独立声明式协议、完整接口文档和确定性安装包构建，处理任务查询、鉴权成片获取和媒体顺序映射。
- `backend/internal/app/model_capability_kacang.go`、`web/src/lib/model-capabilities.ts`：v4 默认参数；统一能力校验限制素材合计数量、视频总时长和尾帧。
- `web/src/components/canvas/canvas-video-prompt-tools.tsx`：按模型能力显示首尾帧，未声明能力的原模型行为保持。

## 用户头像

- `web/src/lib/default-user-avatars.ts`、`components/layout/user-avatar.tsx`：48款静态头像目录、统一渲染与旧图标兼容。
- `web/src/pages/settings/profile-avatar-picker.tsx`、`profile-pane.tsx`：同屏选择、上传裁剪、预览、取消和保存。
- `backend/internal/auth/avatar_presets.go`、`avatar.go`：精确编号校验与新账号一次性随机分配，复用原头像字段及事务写入。
- `web/public/avatars/spirit-v1/`、`scripts/generate-profile-avatars.mjs`：固定DiceBear Core 10.7.0 / Styles 10.6.0 Glass离线生成的圆形SVG、哈希清单和第三方许可，关闭动画且不增加产品运行时依赖；保留尚未发布的48个预设编号。

## 精灵宠物

- `app/appearance_sprite.go`、`handler/appearance_sprite.go`：精灵包校验、管理员导入、图集读取和启用边界；资源引用复用外观保护。

## YuxiBox SD 视频

- 三个 Provider 的声明式合同与独立包：`plugin-packages/yuxibox-sd-video/`；生成入口 `generate-yuxibox-sd-video.mjs`，完整文档嵌入后生成 `.yingce-plugin` ZIP。
- 默认能力：`backend/internal/app/model_capability_yuxibox.go` 和 `web/src/lib/model-capabilities.ts`；管理端协议切换沿用 `changeChannelModelCapability`，不自动改积分售价。
- 协议、后端能力和管理端切换回归：`yuxibox_sd_video_test.go`、`model_capability_yuxibox_test.go`、`web/test/yuxibox-video.test.ts`。管理端连接测试采用当前模型的默认时长，避免固定 6 秒误伤枚举模型。

预演台 Chrome 验收位于 `web/scripts/previs-p0-chrome-e2e.mjs`，使用真实 DEV 复现台与浏览器鼠标事件。点击驱动检查按钮及祖先的可见性、动画和命中位置，移入鼠标后再次等待坐标稳定，避免弹窗入场缩放把「留在预演台」点击送到遮罩。保存失败的关闭保护仍由 `canvas-previs-workbench.tsx` 和保存协调器处理。

AI 拆图的编辑目的与语义工具约束位于 `web/src/lib/canvas/canvas-image-layer-plan.ts`（`applyImageLayerPlanningPurpose`）；页面 `use-canvas-media-tools.ts` 对新规划和历史规划使用同一约束后再进行边界校准。默认 `recompose` 要求修补后的不透明背景与必要前景；明确选择 `materials` 才保留原图副本。连续照片不自动输出局部矩形碎片，完整嵌入场景保留原像素。简洁弹窗提供原图框选、补充要求、视觉规划模型与拆分模型选择，页面自动先规划再拆分，默认不自动另存第二组素材；`canvas-image-layer-controls.tsx` 提供完成后免费另存入口。节点标题由 `imageLayerTargetName` 提取短名称，生成计划仍保留完整描述。`canvas-generation-task-sync.ts` 按移除标记设置初始可见性并据此生成首张合成图。`canvas-node-size.ts` 的 `fitImageMaterialNodeSize` 在素材创建和 `canvas-node-media-content.tsx` 解码后复用，避免极宽素材撑大布局；不增加后端或模型协议。

AI 拆图每层的 `generation.prompt/background` 由 `canvas-image-layer-plan.ts` 要求规划模型填写，`canvas-image-layers.ts` 校验角色与允许字段并附加本层输出约束。`use-canvas-media-tools.ts` 保存编译后的独立提示词与配置，`canvas-image-layer-extraction.ts` 在收费调用前校验全部参数并原样传递本层提示词；不再拼接总体要求或其他层描述。`use-canvas-generation-retry.ts` 继续读取子节点保存的提示词与配置；已有界面和展示链路不变。

最终拆图显示与合成使用 `canvas-image-layers.ts` 的 `validateImageLayerOutput`，只拒绝完全透明空图，不再按背景/前景 alpha 拦截有效产出。`hasUsableLayerTransparency` 的既有阈值仍用于条件去背景；任务消费、提取服务、原图提取、局部修补产出和组重合成都使用同一最终验收。原图局部修补的输入仍保留不透明底板校验，尺寸、资源、数量、像素上限及取消检查不变。原生多图返回多张不透明候选时保留输出顺序，不猜角色或修改像素。

## 后端调用链

AutoDL 画面规格由 `app/model_capability_screen_spec.go` 读取官方插件工作流合同（精确工作流优先，未声明的 ID 回退到 `*` 默认预设），校验所选分辨率及默认值，允许自定义标签；`task_creation.go` 在价格选择之前归一化，任务校验与 `provider_video.go` 再次使用同一规则。前端 `lib/video-screen-specs.ts` 管理插件预设、所选规格与工作流切换，`ModelCapabilityEditor` 复用到系统及自定义渠道；无开关或独立草稿。

```text
HTTP 请求 -> handler -> service（稳定导入面 / 别名）-> app（组合根）-> 业务域包 -> repository/model
                                                                     |
                                                                     -> protocol / payment / generation / outbound
```

`internal/service` 只再导出 `internal/app` 的类型、常量和包级函数，handler/cmd 仍 import `internal/service`。组合根和尚未拆出的业务实现在 `internal/app`。已抽出的域包不得 import `service` 或 `app`（防回环）。共享错误码与 ID/字符串工具在 `internal/kernel`。

## 修改原则

- HTTP 参数与响应只在 handler 处理，业务规则进入 service。
- 页面保留流程协调；可独立理解和测试的算法进入同业务域的 `lib`。
- 新增功能时只更新本页的主要入口，不增加逐文件清单。

- `web/scripts/import-inspirations.mjs`：外部来源同步、等距抽取、缩略图生成与画廊池落盘；产物在 `web/public/inspirations/` 与 `web/public/inspiration-thumbs/`。

## 画布外观

`web/src/lib/canvas/canvas-appearance.ts` 管理预设快照、浅深记忆与默认偏好；`web/src/components/canvas/canvas-appearance-controls.tsx` 管理展开与微调；`web/src/components/canvas/canvas-toolbar.tsx` 限制外观和添加节点浮层尺寸。`web/src/stores/canvas/use-canvas-store.ts` 在创建时写入实际外观与线网格默认值，后续沿用画布持久化。
