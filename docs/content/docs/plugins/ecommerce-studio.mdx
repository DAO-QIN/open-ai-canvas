# 商品套图

商品套图是影策内置的官方创作模块，与短剧创作同级，侧栏入口位于「短剧 Agent」下方；创作首页也可打开 /create/product-images。用户端插件中心不展示该模块。内部继续按 yingce.plugin/v1 维护，插件 ID 为 ecommerce-studio。每张原图对应一个商品，默认交付 3 张主图、5 张详情图和 3 个标题。模块默认关闭。

## 使用与开放

管理员在 /admin/ecommerce 选择能够理解原图的创作模型，以及支持参考图的生图模型，配置有效规格、默认数量和编排限制，再明确开放。创作模型统一负责策划、逐图细化和商品标题，各步骤仍独立执行、计费。功能开放页、插件管理页和商品配置页共用 plugin_platform_states 的同一记录；ecommerceEnabled 仅是公开投影。配置保存与功能开放相互独立，保存配置不自动开放。

平台开放后用户默认启用，无须安装。平台开放状态、个人启用状态及账号状态决定是否能够新建或派发步骤；插件中心开关不影响商品套图。后台「功能开放」将商品套图放在短剧创作下方，独立显示开放状态。个人停用位于商品工作区的「全自动与个人预设」，停用后可在同一工作区重新启用，只影响本人。

审核模式先确认策划费用，生成两组方案和标题，修改后确认整套、某商品或某分支的后续费用。高级全自动模式在开始前确认商品、模型、规格、数量和整套预算。单图调整保留旧图、其它图片与标题；整套重做建立新轮次。追加图片先进行补充策划，已有成品继续保留。

默认页面突出上传、名称、真实卖点、数量、风格和主操作。模型、平台、市场、语言、规格和专业提示词收在高级设置。个人默认设置使用名称为 default 的版本化预设，后续导入采用该设置；已有商品和接受的方案不会因此变化。

## 关闭、暂停与恢复

关闭平台或个人启用状态时，将未完成轮次持久化为暂停。已提交的文本、生图任务继续执行、保存、查询和结算；未派发步骤停止。重新开放不会自动恢复，用户重新报价并明确继续。切换插件中心不暂停商品轮次。

历史读取、标题复制、当前或历史轮次导出只校验登录与对象归属，关闭后仍然可用。归档同样保留在途任务的收尾记录及历史资源。

网页关闭不影响已授权流程。编排器随宿主 worker 启动和维护退出，以数据库租约、租约代次和阶段唯一键协调多个实例。默认每用户同时推进 3 个商品，文本并发 2、生图并发 4、单商品生图并发 2；宿主更小的任务限制继续约束入队。等待异步结果仍占相应容量，每轮每商品最多派发一个步骤。

结果不明时保留原任务、账单和请求快照。恢复入口查询已知上游任务或恢复原媒体保存，不发起新的付费生成。无法安全查询的文本结果要求在任务中心核对，不把网络超时直接当成可重试。已明确失败的步骤须由用户重新确认费用后重试。

## 策划合同

主图和详情分别总策划、分别确认。每个槽位严格匹配 slotId、kind、主题及准确文案；逐图细化使用已接受方案与配置快照，生图始终以原商品资源作为参考。

规则区分用户确认的卖点、原图可见特征与未知信息，不从外形补造材质、容量、功效、认证或未见结构。纯图禁止新增排版文案。有字图片提交准确的用户确认文案。结构校验不能保证最终图像中的文字或真实性，成图仍需审核。

有限 JSON 修复来自归档已有规则：字段别名、可证明的层级纠正和有界外层括号修复。原始响应、修复记录与快照保留；修复失败不自动调用模型。单图调整只接受提示词与文案，客户端不能替换内部分析、视觉结构或槽位身份。

全局默认配置只影响后续商品。对已有轮次的未派发步骤变更模型或规格需要显式应用和重新报价，已提交任务的原参数及路由保留。修改已接受的视觉规则需建立新轮次。

## 可选智能质检

用户端提供“智能质检”开关，默认关闭。高级设置第一行是“创作模型”和“审查模型”，审查模型位于原标题模型位置；下一行保留生图模型。开启质检后用户可自行选择支持两张图片的审查模型，默认使用后台配置，可以与创作模型相同或不同。更换需重新报价并授权，旧版本和已派发任务保留原模型。后台关闭质检能力阻止新的质检授权，已获批步骤仍按原模型快照收尾；商品模块和个人停用的暂停规则继续生效。

每张成图保存后，通过一个独立 quality 文本任务对照原图、成图、用户确认事实及已接受方案检查商品一致性、准确文案、事实依据和用途。结论为 pass（未发现明显问题）、attention（需检查）或 undetermined（无法判断），附具体依据与处理建议。质检不能保证商品事实或小字一定正确，使用前由用户核对。

服务端为质检补充已校验归属的原图和成图实际像素尺寸；画幅按资源尺寸判断，尺寸未知时不能从模型预览猜测。预览缩放或拼排也不能单独作为商品比例改变的证据。

检查结果绑定图片版本，旧图不继承新图结论。成图在检查中、失败或结果不明时仍保留并可导出；没有自动重生成或自动付费重试。明确失败只重试检查，须重新报价确认；结果不明查询原任务。单图重做生成一个新图片版本及对应检查。质检设置改变用于新轮次，不追改旧版本或已有任务。JSON 响应仅去除外层 Markdown 围栏，不增发修复模型请求。

费用计入生成阶段报价，审核模式的策划阶段不提前派发质检。默认 3/5 套图开启质检后增加 8 次文本调用；全自动共 19 次文本、8 次图片。原子入队、预算、价格签名、积分结算、用户归属和容量限制均复用现有任务合同。检查原始响应及版本关联保存在现有步骤记录，ZIP 清单包含所选版本的检查结果，无新增数据库迁移。

## 计费与事务

父商品、轮次和策划记录不产生额外费用。每次实际模型调用对应已有 canvas_text 或 canvas_image 任务、积分预授权和账务记录；无需建立画布，也不把商品 ID 当作画布 ProjectID。

默认完整套图在无重试时为 11 次文本调用、8 次生图：两次分支策划、一次标题、八次逐图细化、八次图片。审核模式分阶段授权，全自动限定整套范围。预算是消费上限，不是一笔新的收费。

报价有效期 15 分钟，流程授权有效期 2 小时。文本报价以有界最大提示词和最大输出预留估计上限；成功后按既有计费合同结算。模型、价格、预算或余额变化时暂停未派发步骤，已有成品保留。

操作标识和修订号防止双击及过期写入。子任务、积分预授权、步骤关联和预算占用在同一事务提交；入队中断通过保存点整体回滚。重启和多 worker 竞争不能新增第二笔同阶段付费任务。

## 资源和导出

原图及成品使用已有资源库。原图、所有历史图片版本加入引用检查；商品结构数据计入账号存储用量，媒体继续使用原有容量规则。

ZIP 默认导出当前轮次选中的成功图片、标题和 manifest.json，按商品与主图、详情分类，清单列出缺失内容。历史轮次可以单独导出。跨用户或失效资源在发送 ZIP 前校验失败，不下载伪装成压缩包的 JSON 错误。

送入画布直接复用资源 ID，通过现有画布同步合同建立节点，不再次生成或上传。先读取实际图片尺寸，复用画布媒体尺寸规则，再按行高与列宽留出间距；图片加载后仍保留实际比例和排版。

## 维护边界

业务位于 backend/internal/ecommerce，负责策划规则、预设、流程、状态和交付；app/ecommerce_bridge 绑定账号、目录、任务、积分、资源与 worker。service 仅导出别名，handler 负责 HTTP 边界。

用户端位于 web/src/pages/product-images，服务端数据使用按用户隔离的 React Query；API 统一 http，ZIP 使用 http.raw。后台使用独立管理员 token 和控件。SDK 的 applications 只绑定受信内置应用及固定入口、报价、授权生成和导出；上传清单不能自行登记特权路由或持久 worker。

迁移版本为 51，接续当前版本 50。移植的 MIT 通知保存在 backend/internal/ecommerce/THIRD_PARTY_LICENSE。

首版不包含店铺授权、自动上架、订单库存、商品视频或用户自有对象存储。真实模型质量与上线环境联调记录见待测试文档。
