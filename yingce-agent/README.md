# yingce-agent

独立的 Agent Node 运行时。它不连接数据库，也不执行计费、审批或画布写入。

后端在 `YINGCE_AGENT_URL` 非空时把一轮会话交给本服务，并在自己的网络地址上提供一次性 bridge token。Node 只通过该 bridge 把模型、工具和事件交回 Go。远程调用失败时不会回退到后端内嵌进程，避免同一步执行两次。

本地开发不设置 `YINGCE_AGENT_URL`，后端仍在本进程启动 Node。生产 Compose 必须同时提供镜像、`YINGCE_AGENT_TOKEN` 和 `YINGCE_AGENT_BRIDGE_HOST`。

## 预热进程

`YINGCE_AGENT_PREWARM`（0–4，默认 2，0 关闭，大于 4 按 4）设定预先启动的空闲 Pi 运行时数量。预热进程的启动命令、环境和工作目录与现启动的进程相同，已加载依赖并等待输入。一轮会话取得名额后使用最早启动的预热进程，并立即补足；没有可用的预热进程时照常现启动。预热进程不占同时对话名额（`MAX_CONCURRENT_SESSIONS` 或后台设置的上限），`/healthz` 的 `warm`、`prewarm` 分别是当前空闲数和目标数。

预热进程在分配前退出会被替换。连续 3 个在启动后 10 秒内退出时暂停补充，等待时间从 1 秒起倍增，最长 60 秒，每次暂停记一条日志。闲置超过 30 分钟的预热进程会被替换。收到 SIGTERM/SIGINT 时先结束空闲的预热进程，之后的停止流程不变。每个预热进程常驻一份 Node 内存，内存紧张时可调小或设为 0。
